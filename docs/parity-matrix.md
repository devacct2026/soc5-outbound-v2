# SOC5 Outbound v2: source-parity matrix

Branch `feature/source-parity-completion`. Source reference: the original Laravel/React repository (read-only clone, never
modified, no production service contacted). Authority order applied: the latest explicit decisions in the task, then
[`backend/09-business-decisions.md`](./backend/09-business-decisions.md) (46 decisions + APR-3 final rejection), then the
executable source behavior.

Status vocabulary (used in every row; nothing is rounded up):

| Status | Meaning |
|---|---|
| **Verified locally** | Implemented and exercised by an automated test in this repository against disposable resources (in-memory stores, a throw-away PostgreSQL cluster, stubbed `fetch`, a fake WebSocket, a mocked-network browser). |
| **Live-unverified** | Implemented and locally tested, but a provider contract detail could not be confirmed offline. It has never run against SeaTalk, Google or a Supabase project. |
| **Gap** | Not implemented, with the reason. |

Audit leads were treated as leads, not facts: each was re-checked against the source and the V2 code before work started.
Several were already partly true (for example the API already had edit/cancel/reassign/bulk endpoints; the gaps were the
provider, routing, UI, auth flows and data semantics).

## Approved-decision and safety notes

* **APR-3:** unchanged and re-tested through the UI matrix: a final FTE-Ops rejection exposes no edit, resubmit or cancel.
* **Terminal-row guard** (final/legacy rejection, cancelled) is respected by the new triggers; propagation skips those rows.
* **Revocation (OPS-3):** the API still loads the profile on every request (`must_change_password` included). Disabling an
  account takes effect on its next request; an already-issued JWT keeps working at the Supabase Auth layer until expiry but
  confers no data access. The measured live delay remains open.
* **Secrets:** one-time passwords are never stored (idempotency replay is intentionally not used for those endpoints);
  tokens only travel in URL fragments; no refresh token reaches the browser.
* **Pending accounts:** a 401 from an operational endpoint no longer signs the user out; `GET /auth/status` reports
  `PENDING_APPROVAL`/`DISABLED` so the user sees why they have no access.

* Settings page and administrator-configurable reporting defaults (KPI-4/5 UI) are not built; the database already versions
